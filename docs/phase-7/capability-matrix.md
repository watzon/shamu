# Adapter capability matrix

Every Shamu vendor adapter ships a frozen `capabilities.json` manifest
(PLAN.md § 1 / G8 — capabilities are declared at build time and
immutable at runtime). The shared contract suite keys scenario skip /
run decisions off these fields, and the matrix below is the canonical
"which adapter supports what" view.

## Schema

The schema lives in `packages/shared/src/capabilities.ts`. The columns
used below come in two flavors:

- **Feature parity** — boolean columns derived from the
  `CapabilityFeature` predicates in
  `packages/adapters/base/src/capabilities.ts`. These are the
  features the contract suite's `scenario.requires` list keys off;
  a `no` here means the adapter opts that scenario out of its
  contract run.
- **Enum / detail fields** — the underlying union types. They show
  _how_ the adapter satisfies a capability (e.g., `interrupt: "cooperative"`
  vs `"hard"` vs `"none"`), which matters when picking a vendor for
  a specific workflow but isn't reducible to a single bool.

## Phase 9.B observations — declared vs. actual (hand-edited)

Appended 2026-04-19 by Phase 9.B.7 ([`docs/phase-9/adapter-smoke.md`](../phase-9/adapter-smoke.md)).
This subsection is NOT regenerated by
`bun scripts/generate-capability-matrix.ts` — if you re-run the
generator, re-append from git history.

The Phase 9.B live smokes validated the declarations above against
real vendor output. All non-usage-token declarations (`resume`, `fork`,
`interrupt`, `customTools`, `patchVisibility`, `patchEvents`,
`streamingEvents`, `permissionModes`, `mcp`, `sandboxing`) held on
every adapter where the smoke exercised them. The only declared-vs-
actual delta worth capturing at the matrix layer is the one below.

### Declared `usageReporting: "per-turn"` vs. live per-turn token counts

Five of seven adapters declare `usageReporting: "per-turn"` with a
subscription-shaped `costReporting`. The live smokes found two
distinct behaviors hiding under that one declaration:

| Adapter  | Declared `usageReporting` | Live `usage.inputTokens` / `outputTokens` | Declared `costReporting` | Live `cost` event                          | Fragment |
| -------- | -------------------------- | ----------------------------------------- | ------------------------- | ------------------------------------------ | -------- |
| codex    | per-turn                   | populated (e.g., `input=55778, output=5`) | subscription              | `usd=null confidence=unknown source=subscription` (on ChatGPT-OAuth) | [smoke-codex.md](../phase-9/smoke-codex.md) |
| opencode | per-turn                   | populated from OpenCode's `usage` envelope | subscription              | `source=subscription` stamped correctly    | [smoke-opencode.md](../phase-9/smoke-opencode.md) |
| cursor   | per-turn                   | **zero** (`in=0 out=0`) — Cursor ACP server does not populate `usage.inputTokens` / `outputTokens` in its `session/prompt` result | subscription              | `usd=null confidence=unknown source=subscription` | [smoke-cursor.md](../phase-9/smoke-cursor.md) |
| gemini   | per-turn                   | not-observed (blocked-on-vendor — Google-account ToS appeal) | subscription              | not-observed                               | [smoke-gemini.md](../phase-9/smoke-gemini.md) |
| amp      | per-turn                   | not-observed (blocked-on-vendor — paid credits required) | subscription              | not-observed                               | [smoke-amp.md](../phase-9/smoke-amp.md) |
| pi       | per-turn                   | **zero** (`in=0 out=0`) — pre-existing 7.E followup: `get_session_stats` wiring on `turn_end` not yet implemented | subscription              | `usd=null confidence=unknown source=subscription` | [smoke-pi.md](../phase-9/smoke-pi.md) |
| claude   | per-turn                   | populated (pre-9.B; not a 9.B.x track)    | **native**                | native USD stamped                         | — |

**Conclusion.** The declaration `usageReporting: "per-turn"` is
technically accurate for every row — a `usage` event IS emitted per
turn — but doesn't distinguish "per-turn with populated token counts"
from "per-turn with zeroed tokens because the vendor doesn't publish
them" (Cursor: vendor-side; Pi: adapter-side followup).

**Options:**

1. **Tighten the vocabulary.** Add a subvariant like `"per-turn-empty"`
   or split the field into `usageReporting.shape` (`per-turn | batch | none`) + `usageReporting.tokens` (`populated | zeroed`). A schema
   change in `packages/shared/src/capabilities.ts` + manifest updates
   + contract-test plumbing.
2. **Keep the matrix at the declaration layer** and track the observed
   population behavior here in the observations subsection. Lower cost;
   captures the drift but doesn't let the contract suite key off it.

**Current choice: option 2.** The observations subsection lives with
the matrix; the 9.B.7 digest's "theme T3" follow-up keeps option 1 on
the table if another adapter lands with a third behavior (e.g.,
batched-usage-on-session-close) that warrants the schema churn.

### Other capability-matrix notes surfaced by 9.B

- **`mcp: "none"`** on Cursor, Gemini, Amp, Pi matches live
  behavior. None of the four stream MCP tool invocations through the
  adapter during a plain turn. `mcp: "stdio"` on Codex + OpenCode is
  declared; 9.B did not exercise the MCP path end-to-end on either
  (the smokes were bare prompts). Not a declared-vs-actual drift —
  just coverage note.
- **`permissionModes: ["default", "acceptEdits"]`** held on every
  adapter where a permission-requiring tool call was exercised
  (Cursor: ReadFile under default policy; other adapters: either
  blocked-on-vendor or bare-prompt smokes that triggered no tools).
- **`customTools: false`** on Cursor, Codex, Amp, Gemini, Pi held —
  no custom-tool injection surface was exercised (or even attempted,
  since the manifest-declared `false` opts those contract scenarios
  out). `customTools: true` on Claude + OpenCode inherits trust from
  Phase 7 contract runs; 9.B did not re-exercise.
- **`interrupt: "cooperative"`** held on every adapter (no smoke
  exercised a live mid-turn interrupt; hermetic tests cover the
  `session/cancel` + equivalent paths).
- **`patchVisibility: "events"`** — every adapter's patch events
  project into the stream; fragment-level observation only
  (no declared-vs-actual drift).
